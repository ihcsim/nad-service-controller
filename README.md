# nad-service-controller

This controller connects a `Service` resource to secondary pod networks created by Multus.

The controller watches for events associated with `Service` resources annotated with the `isim.dev/network: <network-name>`. Matching the `Service` with pods in the secondary network with the name `<network-name>`, the controller manages `EndpointSlices` resources to ensure the pods' secondary network IP addresses are captured in the slice's endpoints. The states of the pods are reflected in the endpoints' conditions to ensure kube-proxy is routing traffic only to ready pods.

## Quick Start

## SBOM And Provenance

The image SBOM is generated by `ko` in the SPDX format. The release workflow uses  [`actions/attest`](https://github.com/actions/attest) to create the build provenance.

To attest, use the `gh` CLI:

```sh
gh attestation verify oci://ghcr.io/ihcsim/nad-service-controller --repo ihcsim/nad-service-controller
```

## Development

Development requires the following tools:

* [go](https://go.dev/doc/install)
* [golangci-lint](https://golangci-lint.run/)
* [kubectl](https://kubernetes.io/docs/tasks/tools/)
* [kind](https://kind.sigs.k8s.io/) - for cluster testing
* [ko](https://ko.build/) - for image building and pushing to a registry

Go code targets:

```sh
# build the src
make build

# run unit tests
make test

# run main with go run
make run

# use golangci-lint to check for linting issues
make lint
```

Working with OCI images:

```sh
# use ko to build and push the image to a local registry
make image-local

# use ko to apply the Deployment resource YAML to the cluster using the image
# built with ko, targeting your current context cluster
make apply

# use ko to delete the Deployment resource from the cluster in your current 
# kubeconfig context
make delete
```

Set up a KinD cluster for development:

```sh
# create a KinD cluster with Multus and Whereabouts CNI
make kind multus nad whereabouts

# delete the KinD cluster
make purge
```
